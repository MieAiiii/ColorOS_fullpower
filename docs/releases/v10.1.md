# ColorOS特性补全 v10.1

10.1 适配性更新：让模块按当前机型真正支持的能力运行，而不是把所有 ColorOS 16/17 当成同一台机器。

## 主要更新

- 新增运行时能力探测 `webroot/adapt.sh`：读取 ColorOS 主版本，检查 Settings 键与 PQ 属性是否真实存在，检查晕动桥接是否安装。
- 新增适配策略 `ADAPT_MODE`：
  - `auto`（默认）：ColorOS 17 且检测到材质模糊与全屏 AOD 键时走全量；其余走兼容。
  - `compat`：只应用稳定项；6 个实验项强制归零，未声明的键不创建。
  - `full`：显示全部项，但物理不支持的项仍然禁用、不写入。
- `advanced.sh` 只写当前系统存在的 Settings/PQ 键；不支持的项记 `N/A`，不会用 `settings put` 造出假开关。
- `ctl.sh status` 新增 `ROM_MAJOR`、`ADAPT_MODE`、`ADAPT_EFFECTIVE` 和 18 个 `SUP_*`；新增 `ctl.sh adaptmode auto|compat|full`。
- WebUI 设备卡下方新增“适配策略”卡片，可切换自动 / 兼容 / 全量；功能行按能力动态禁用，兼容模式下隐藏未支持的实验项。
- `system.prop` 去掉对媒体面板模糊、AOD 硬件支持、模糊性能提示的强声明，交给系统按硬件自行判断。
- WebUI 执行超时从 2.4 秒放宽到 5 秒，适配探测在低端机上不会轻易超时。

## 适配判定

| 标志 | 判定依据 |
|---|---|
| `MATERIAL_BLUR` / `MATERIAL_STROKE` | 对应 `system` 键存在 |
| `FULL_AOD` / `AOD_CHARGE` / `AOD_WORKSHOP` | 对应 `secure` 键存在 |
| `ALL_DAY_AOD` / `FOLLOW_HAND` / `GAME_MEMC` | 对应 `secure` 键存在 |
| `GAME_COLOR` | `system game_color_enhance` 存在 |
| `HDR10P` / `HDR10` / `HDRVIVID` / `ULTRA_RES` / `MML_COLOR` / `AI_SDR` | 对应 `persist.vendor.sys.pq.*` 存在 |
| `LEGACY` | ColorOS ≤16 或 `ro.oplus.gaussianlevel` 存在 |
| `MOTION` | 桥接包 `com.workbuddy.antidizzybridge` 已安装 |

## 验证范围

- 已通过：`bash -n` 脚本语法、`node --check` WebUI JS、`tools/validate_webui.py` 结构校验。
- 已通过：`tools/adapt_mock_test.sh` 用 mock 的 `getprop` / `settings` / `pm` 覆盖：
  - ColorOS 17 全量：`auto → full`，全部 `SUP_* = 1`，材质键与 HDR PQ 正常写入；
  - ColorOS 16 精简：`auto → compat`，材质/全屏 AOD/PQ 不写入，日志记 `N/A`；
  - ColorOS 17 残缺：缺少材质/全屏 AOD 键时 `auto → compat`，对应项禁用；
  - 显式 `compat` / `full` 与 `adaptmode` 写配置。
- **未做真机复测**：10.1 开发时手机已断开，以上为 PC mock 结果；真机表现以实际机型为准。

## 升级提示

- 10.0 → 10.1 可直接覆盖安装，桥接 APK 签名未变，不需要重新卸载桥接。
- 若从 9.x 升级，仍按 10.0 的桥接签名说明处理：卸载旧 `AntiDizzy Bridge`，安装模块内 APK，在 LSPosed 重新勾选“系统框架”。
- 安装后默认 `ADAPT_MODE=auto`；想强制显示全部项可在 WebUI 切到“全量”，但物理不支持的项仍不会写入。

## 安装

下载 zip 后在 KernelSU 管理器中安装并重启。晕动功能需要 LSPosed；首次启用后，在“晕动控制”二级页手动打开显示开关。
